# S3 service module / Módulo de serviço S3

## MVP behavior / Comportamento do MVP

UX-5A provides explicit native bounded UTF-8 text/JSON-as-text preview under [ADR-0018](../decisions/ADR-0018-bounded-text-preview.md). UX-5B adds `/s3/preview/image` and its separate bounded/re-encoded PNG content GET for static PNG/JPEG under [ADR-0019](../decisions/ADR-0019-raster-preview-isolation.md), with [local evidence](../spikes/ux-5b-results.md). Original name/type/bytes remain on attachment download; preview output is always a separate `preview.png`. No expanded mutation/signing capability is implied. / Texto limitado e imagens PNG/JPEG estáticas têm contratos próprios; imagem usa página e GET separado com reencode PNG. Download preserva nome/tipo/bytes originais; saída da prévia é `preview.png`. Sem inferir mutações/assinatura.

Current requirements now follow the user-confirmed [expanded operational scope](../product/s3-management-scope.md), including preview, deletion, clipboard, signed download links and copy/move within the first current delivery. The historical optional/deferred labels below no longer define its schedule. Capabilities remain planned until separately implemented and verified; advanced bucket configuration is excluded. / Requisitos atuais seguem o escopo operacional ampliado: capacidades entram na primeira entrega, sem configurações avançadas. Rótulos históricos de opcional/adiado não definem mais o cronograma; implementação/evidência continuam separadas.

Current Phase 3 behavior includes bucket creation, bounded upload, marker creation and selectable POSIX CLI equivalents, in addition to Phase 2 reads. See [guide](../development/phase-3.md) and [evidence](../spikes/phase-3-results.md). Historical planning below is not a blanket compatibility claim. / O comportamento atual inclui essas escritas; a tabela histórica não certifica compatibilidade completa.

| Buckets  | List, create with server validation, open basic details; no rename                                   |

## Errors and limits / Erros e limites

Initial object page size is 50 with a continuation token. Do not load whole collections or count every object while rendering a bucket list. Handle `NoSuchBucket`, optional absent tags, unavailable endpoint, and unsupported operation predictably. User messages must contain no secrets, stack traces, or internal responses; technical logs need diagnostic context without credentials/content.

## Deferred destructive operations / Operações destrutivas adiadas

Object deletion, deleting an empty bucket, and preview are MVP+ candidates. “Empty and delete” requires explicit pagination, batching, version, and delete-marker behavior before exposure. Rename is copy plus delete, not atomic. Metadata edits may copy an object and create a version; costs/failure modes must be visible. Specific-version deletion remains out of initial MVP+.

## Acceptance evidence / Evidência de aceite

Before calling a behavior supported, run integration tests against a pinned emulator for nested prefixes, pagination, boundary/over-limit upload, large streaming download with controlled memory, special/Unicode object keys, failure during streaming, and versioned buckets where applicable.
