# ADR-0013 — visual/UX evolution boundary / Limite da evolução visual/UX

- Date / Data: 2026-10-15.
- Status: ACCEPTED CSS selection after UX-0; UX-1 product build integrated, verification/acceptance tracked separately / SELEÇÃO CSS ACEITA após UX-0; build UX-1 integrado, validação/aceite no registro próprio.

## UX-0 selection (historical gate) / Seleção UX-0 (gate histórico)

2026-10-20: [ADR-0023](ADR-0023-hig-fluidity.md) supersedes V1's gradient/decorative glow and the old fixed visual recipes for the maintainer-authorized cohesive HIG iteration. Build, accessibility and capability/security contracts remain; historical test evidence is not rewritten. / ADR-0023 substitui estética/receitas congeladas, preservando contratos e evidência histórica.

2026-10-20: [ADR-0020](ADR-0020-service-catalog-navigation.md) supersedes V2's home hierarchy and navigation only: Home becomes a service catalog without emulator reads; buckets move to `/s3`, status/refresh become contextual. Earlier V2 decisions/results remain historical. / ADR-0020 substitui apenas hierarquia/navegação V2: Início sem consultas ao emulador, buckets em `/s3` e status/atualização contextuais; histórico preservado.

Select Tailwind CSS/CLI 4.3.3, build-time only and without Preflight; reuse semantic tokens and native auto/explicit theme semantics. Exact versions/lockfile, real escaped Qute rendering, deterministic isolated Maven/Docker builds, direct MIT licenses and browser candidate diagnostics are recorded in [UX-0 evidence](../evidence/ux-0-css-results.md). Default additive Pico 2.1.1 is not selected because the tested overlay introduces CSP-blocked data images and dark contrast failures; DaisyUI is unnecessary for the tested slice. Do not generalize those findings to all custom Pico configurations. Production assets/routes are unchanged; UX-1 must implement real packaging, component migration and reviewed removals. CSS utilities are full literal tokens in Qute branches, never built from emulator data. Keep generated output separate from authored sources and preserve root lint rules; macro-specific exceptions apply only to the isolated input. All destructive/preview/presigning and ADR-0012 gates remain unchanged.

Selecionar Tailwind/CLI 4.3.3 no build e sem Preflight, reutilizando tokens/temas. Evidência vinculada registra versões, Qute, builds isolados, licenças e diagnósticos. Pico padrão aditivo não foi escolhido por bloqueios CSP/contraste; DaisyUI não é necessário nesta fatia, sem generalizar para toda customização Pico. Produção permanece igual; UX-1 integra empacotamento e migração. Classes literais completas, fontes/gerados separados e exceções de macro somente na entrada isolada. Gates de capacidades/P2 permanecem.

### V4 continuation authorized — 2026-10-17 / Continuação V4 autorizada

The maintainer authorized continuing after the local preview-transport correction and recorded V3 checks. Implement V4 motion/feedback locally; this is not a new report of human V3/assistive-technology review, final-image approval or a waiver of pending release gates. V5 self-hosted fonts remains deferred by D1. Keep system fonts, CSP, URL-only preferences and native navigation/forms.

Mantenedor autorizou continuar após correção local de transporte e checks V3 registrados. Use the existing 180ms token for a 4px card-entry translation through `@starting-style`, without fading text, staggering, looping or delaying focus. Final cards are visible with no transform even if the at-rule is unsupported. CSS-only `@view-transition { navigation: auto; }` permits browser-managed same-origin document transitions where supported, with root animations capped at 180ms and no added delay. No SPA interception, `startViewTransition()` call, history rewrite, storage or new dependency. Slow/ineligible/unsupported navigations may skip the effect; normal navigation remains authoritative. Reduced-motion disables entry/ordinary transitions, opts out of cross-document transitions and explicitly disables transition pseudo-element animations. A transition duration is not a navigation/HTTP latency bound.

Token 180ms para entrada dos cards por translação de 4px via starting-style, sem fade de texto, escalonamento, loop ou atraso de foco. Estado final visível/sem transformação mesmo sem suporte. View Transition CSS entre documentos da mesma origem, quando suportada, com animações root de 180ms sem atraso; sem SPA/interceptar links, reescrever histórico/storage ou dependência nova. Existing bucket/key clipboard gains explicit pending/success/failure presentation state after the same actual promise, plus a persistent 3px status border (120ms color transition) beside the existing localized live text. No optimistic success, timeout, auto-dismiss, command-copy capability or duplicate toast. Failure retains manual selection/focus. Skeletons remain static and notices retain indefinite visibility under ADR-0017. [V4 evidence](../evidence/visual-v4-results.md) owns executed checks and remaining acceptance.

Clipboard existente de bucket/chave ganha estado visual pendente/sucesso/falha ligado à promessa real, borda de status persistente 3px com cor em 120ms e texto live traduzido existente. Sem sucesso otimista, expiração, cópia de comando nova ou toast duplicado; falha mantém seleção/foco. Skeletons estáticos e avisos indefinidos conforme ADR-0017. Registro V4 reúne checks/aceite.

References checked 2026-10-17: [MDN starting-style](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@starting-style) reports Baseline 2024 newly available, not old-browser coverage; [Chrome cross-document guide](https://developer.chrome.com/docs/web-platform/view-transitions/cross-document) documents same-origin opt-in and skipped/ineligible navigation. Cross-document transitions are not assumed to share same-document Baseline support; only tested host Chrome behavior is claimed. / Referências consultadas não comprovam navegadores antigos nem equivalência entre suporte de transições intra/interdocumento; registrar só compatibilidade executada.

Chaves longas quebram sem truncar; rolagem horizontal só na tabela, não na página de 390px. V4 e gates finais continuam separados.

## Initial proposed direction (historical) / Direção inicial proposta (histórico)

Keep Quarkus/Qute/htmx, local assets, system fonts, constructor-injected adapter boundaries and native-page/form fallbacks. Prefer build-time Tailwind subject to the UX-0 comparison/build/CSP/license gates in the [execution plan](../product/visual-ux-evolution.md). Pico remains a candidate; DaisyUI is an optional Tailwind plugin. No dependency/version is selected or installed here, and no global lint relaxation or CDN is permitted.

Manter stack, assets/fontes locais, limites e fallback nativo. Preferir Tailwind no build condicionado ao UX-0; Pico é candidata e DaisyUI plugin opcional. Sem dependência/versão adotada, CDN ou relaxamento global de lint nesta ADR.

The user example is a design sketch, NOT a production contract: `object.formattedSize` and `/s3/preview/{object.key}` or `/s3/delete/{object.key}` are not established bindings/routes. Do not paste them as implemented APIs. Preserve existing links/routes and encode opaque keys through the web mapper. Avoid flex display on a table cell if it breaks table layout; use an inner wrapper. Use translated accessible labels and safe icon fragments, not copied unreviewed markup. A `hx-confirm` prompt is not the requested custom modal or a substitute for CSRF/server confirmation.

O exemplo é esboço, NÃO contrato pronto: propriedade/rotas ilustradas não existem como bindings/APIs estabelecidos. Preservar contratos e codificar chaves no mapper. Usar wrapper interno para flex sem comprometer tabela, traduções e ícones revisados. `hx-confirm` não é modal customizado nem substitui CSRF/confirmação servidor.

Stage safe explorer/form feedback first. Preview needs a dedicated bounded-content threat model; deletion needs a dedicated accepted mutation ADR and verified version semantics; presigning is deferred separately. ADR-0002 MVP exclusions, ADR-0007 write boundaries, ADR-0008 original-file attachment policy and ADR-0009 CSP remain in force until explicitly superseded. ADR-0012 P2 proposals remain unapproved. Documentation of future capabilities does not enable them.

Priorizar explorer/formulários seguros. Preview exige modelo de ameaça e limites; exclusão exige ADR aceita e semântica de versões comprovada; assinatura fica separada. ADRs existentes continuam válidas até substituição explícita; P2 da ADR-0012 não é aprovado por este plano. Planejar capacidade não a ativa.
