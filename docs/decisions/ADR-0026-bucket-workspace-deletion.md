## Empty-bucket deletion / Exclusão de bucket vazio

GET `/s3/delete-bucket?bucket=…` is read-only review. POST requires framework CSRF, explicit named submission (`confirm=yes`) and a separate bounded one-use server-held ticket (256-bit random, five minutes, 128 pending). Consume before I/O even on failure. Ignore submitted target fields. Only conservative writable names and a successful never-versioned state are accepted; Enabled/Suspended/unknown/MFA state fails closed. Read a bounded root listing (`maxKeys=1`, no prefix/delimiter); require empty contents, zero key count and explicit non-truncated state. Recheck both immediately before deletion. Never delete objects, folder markers, versions or multipart uploads. A nonempty bucket gives a clear refusal, not an invitation to automatic emptying.

GET apenas revisa. POST exige CSRF, envio explícito e ticket separado limitado de uso único (256 bits, cinco minutos, 128 pendentes), consumido antes de I/O mesmo em falha. Alvo fica no servidor. Só nomes conservadores e estado nunca versionado; estados desconhecidos/versionados/MFA bloqueiam. Listar raiz com limite 1, sem prefixo/delimitador; exigir ausência de objetos, contagem zero e não truncado explícito. Revalidar antes de excluir. Não excluir objetos/markers/versões/uploads multipart; bucket não vazio é recusado sem limpeza automática.

Use a narrowly scoped adapter-owned client, as ADR-0021, with SDK retries disabled and explicit empty DELETE body/Content-Length to prevent URLConnection replay. Close only the owned client. Treat DELETE transport/5xx failures as uncertain, consume the ticket and never automatically retry. Success requires HTTP 204. 403/404/409 remain failures, never optimistic success. Action windows reuse ADR-0025 gates, Cancel focus and uncertainty handling; canonical server forms remain.

Cliente próprio delimitado como ADR-0021, sem retry SDK e corpo DELETE vazio/comprimento explícito para impedir replay de URLConnection. Fechar só o próprio cliente. Falha de transporte/5xx após DELETE é incerta, ticket consumido e sem repetição automática. Sucesso exige 204; 403/404/409 são falhas. Reutilizar gates/janelas/foco/fallback da ADR-0025.

The compliant service must atomically refuse DeleteBucket while objects/versions/markers exist; a listing alone is not authorization or an atomic lock. Bucket names lack a generation precondition: deletion/recreation or external versioning/upload changes cannot be fully excluded. This trusted-local workflow requires no concurrent external writers; it is not suitable for production or arbitrary emulators. Multipart/advanced configuration preservation and bucket-generation identity remain unverified. Test a new object after review, version changes, exact target/neighbor preservation, expired/replayed/tampered tickets, CSRF, permission failures, malformed listings and lost-response single-wire DELETE before acceptance. Do not mutate existing user buckets to test.

Serviço conforme deve recusar atomicamente DeleteBucket com conteúdo/versões/markers; listagem não é lock. Nome não tem condição de geração: recriação/alterações externas não podem ser totalmente excluídas. Fluxo local confiável exige ausência de escritores externos; não suporta produção/emuladores arbitrários. Preservação de multipart/configurações avançadas e identidade de geração não verificadas. Testar concorrência, alvo/vizinhos, tickets/CSRF, erros/listagem inválida e DELETE único com resposta perdida usando apenas fixtures próprias.

## Mapped, not enabled: Empty and delete / Mapeado, não habilitado: Esvaziar e excluir

Subsequent explicit maintainer authorization — 2026-10-22: [ADR-0028](ADR-0028-bounded-bucket-cleanup.md) supersedes this mapped-only status with an independently confirmed synchronous bounded slice. Preserve this original design record as history; no ordinary deletion gate is relaxed. / Autorização explícita posterior habilita fatia síncrona/limitada com confirmação própria, mantendo este registro histórico e todos os gates individuais.

Keep this a separate explicit workflow, not a fallback for failed empty deletion. Before implementation define: never-versioned-only initial scope; fresh bounded paginated inventory including folder markers; concrete object/page/time caps; exact bucket-name confirmation plus independent one-use job authorization and CSRF; server-held immutable target manifest; per-key outcomes; no automatic destructive retries; clear partial/uncertain states and inspect-before-retry; progress that never treats transfer as completion; cancellation stopping future work without rollback; final fresh emptiness check before a separate DeleteBucket; concurrent-writer refusal and identity limits. Suspended/versioned buckets, versions/delete markers, retention/MFA bypass, multipart aborts and advanced configuration are excluded until separate contracts exist. Numeric batch limits and emulator compatibility must be established by a local spike, not invented here. No endpoint, disabled promotional button or bulk implementation is added now.

Fluxo separado, nunca fallback automático. Definir antes de implementar: escopo inicial nunca versionado; inventário paginado limitado com markers; limites concretos de objetos/páginas/tempo; confirmação do nome exato, autorização única de job e CSRF; manifesto imutável no servidor; resultado por chave; sem retry destrutivo automático; falhas parciais/incertas explícitas; progresso real; cancelamento só interrompe trabalho futuro, sem rollback; verificação final antes de DeleteBucket separado; recusa de escritores concorrentes/limites de identidade. Versões/markers de exclusão, retenção/MFA, abort multipart e configurações avançadas ficam fora até contrato próprio. Limites e compatibilidade exigem spike local. Sem rota/botão promocional/limpeza em lote nesta entrega.
