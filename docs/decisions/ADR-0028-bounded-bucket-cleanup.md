# ADR-0028: Reviewed bucket cleanup / Esvaziamento revisado de bucket

Date / Data: 2026-10-22. Status: accepted implementation contract; verification separate / contrato aceito; verificação separada.

## Authorization and scope / Autorização e escopo

The maintainer explicitly selected Implement Empty and delete with independent review/confirmation. This supersedes ADR-0026's mapped-only status, not ordinary empty-bucket or ADR-0027 individual empty-folder gates. Never empty automatically after a failed Delete bucket. Only trusted-local never-versioned buckets, ordinary keys and zero-byte folder entries are eligible. Version histories/delete markers, retention/MFA bypass, multipart abort and advanced configuration remain excluded.

O mantenedor autorizou Esvaziar e excluir com revisão/confirmação próprias. Substitui o estado apenas mapeado da ADR-0026, sem mudar exclusão comum de bucket vazio ou gates individuais da ADR-0027. Nunca esvaziar automaticamente após uma recusa. Escopo local confiável, bucket nunca versionado, chaves suportadas e entradas de pasta de zero bytes; sem versões, bypass de retenção/MFA, abort multipart ou configuração avançada.

## Limits and workflow / Limites e fluxo

- Local protocol spike: 25 exact entries (23 files, two nested folder entries), three pages of ten, conditional If-Match deletes and final DeleteBucket passed on MiniStack in 0.6621001 seconds using UUID fixture `stackemu-cleanup-spike-e84fdf808c1a491dae3d0a21ca27c5bb`, then exact cleanup. This is protocol evidence, not a product benchmark or capacity claim. / Spike local aprovado, não benchmark do produto ou promessa de capacidade.
- Initial policy: at most 25 entries, three pages of ten, 64 KiB per list response, conservative writable names, quoted ETags and known sizes. Unknown/truncated/inconsistent inventories, duplicate keys/tokens, unsupported names, nonzero slash entries and excess limits block before authorization. / Política inicial limitada; manifesto incompleto/desconhecido ou incompatível bloqueia antes da autorização.
- Read-only GET `/s3/empty-bucket` builds a complete immutable server-held manifest and verifies object metadata/version state. Separate 256-bit one-use ticket, five minutes, at most 32 pending manifests. POST requires framework CSRF, exact typed bucket name and explicit submit. Consume before validation/I/O; ignore submitted bucket/key/ETag targets. / GET monta manifesto completo; ticket independente, cinco minutos/32 pendentes; POST exige CSRF, nome digitado exato e envio explícito. Consumir antes de validação/I/O; alvo é o do servidor.
- Synchronous bounded execution, no durable/background job or resume. Cooperative review budget seven seconds; mutation budget twenty seconds, checked between bounded calls (an in-flight call can extend this). No percentage that implies server progress. Cancel/Escape is available before submission, not rollback/cancellation after POST. No concurrency/polling framework. / Execução síncrona limitada, sem job persistente/retomada; orçamento cooperativo de sete/vinte segundos entre chamadas limitadas, sem percentual fictício ou promessa de rollback. Cancelar antes de enviar; não durante POST.
- Before the first mutation and each next key, compare the current complete inventory against the remaining reviewed manifest; never silently adopt new/changed keys. Files first, then deepest empty folder entries. Reuse exact-object deletion port for fresh version/HEAD/ETag checks, independent folder emptiness proof and no-retry conditional single-key DELETE. Reuse empty-bucket deletion port only after a fresh empty inventory. No DeleteObjects API or automatic destructive retry. / Comparar inventário atual com restante revisado antes de cada exclusão; arquivos antes de pastas vazias mais profundas. Reutilizar gates existentes de cada chave e bucket, sem lote opaco ou retry.
- One active cleanup per bucket in this process. Fail fast on conflict/error/deadline; retain per-key acknowledged, failed, uncertain and unattempted outcomes. Bucket success requires its own acknowledgement; partial/uncertain is never success or rollback. Tickets from other operations are invalid. / Uma execução por bucket neste processo; parar em conflito/falha/limite e relatar resultado por chave, sem sucesso global presumido.
- External writers/version changes, same-ETag replacement and bucket name reuse cannot be atomically excluded. Require no external writers in this local workflow; no production/arbitrary-emulator assurance. A late new object may remain after partial removal; never delete it. Final DeleteBucket must refuse a nonempty bucket. / Sem lock atômico contra clientes externos ou identidade de geração; exigir ausência de escritores externos. Objeto novo pode permanecer após remoção parcial, mas nunca entra silenciosamente na operação.

## Dialog communication / Comunicação dos diálogos

Metadata precision: MiniStack ListObjectsV2 preserves fractional seconds while HTTP HEAD Last-Modified has second precision. Compare those cross-protocol timestamps at seconds; keep original listing precision for successive manifest comparisons and require the exact ETag and size. This does not distinguish same-ETag replacements within a timestamp's precision. / Listagem preserva frações de segundo e HEAD possui precisão de segundos; normalizar só essa comparação, mantendo precisão original entre manifestos, ETag e tamanho exatos. Não distingue substituições de mesmo ETag dentro dessa precisão.

Use the HIG skill for one action title, exact target, one short consequence and an explicit action. Remove the redundant Review exact target heading. Keep object ETag, ticket expiry and concurrency caveats in closed Technical details; never hide the irreversibility warning, uncertain/partial state or required confirmation. Apply en/pt-BR parity to creation/upload/deletion/loading/results. Preserve canonical forms, native dialog focus/Escape, CSP/CSRF and response gates.

Usar título único, alvo exato, consequência curta e ação explícita; remover subtítulo repetido. ETag, expiração e concorrência em detalhes técnicos recolhidos, sem esconder irreversibilidade/incerteza/resultado parcial/confirmação obrigatória. Manter idiomas, fallback e gates.
