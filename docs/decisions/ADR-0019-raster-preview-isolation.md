# ADR-0019 — raster preview isolation / Isolamento do preview raster

- Date / Data: 2026-10-16.
- Status: Accepted local HTTP implementation contract; verification recorded separately, final new-image validation deferred / Contrato HTTP local aceito; evidência separada e validação final com imagem nova adiada.

## HTTP integration contract / Contrato de integração HTTP

Transport amendment, 2026-10-16: the [ADR-0018 correction](ADR-0018-bounded-text-preview.md#transport-correction-2026-10-16--correção-de-transporte) supersedes the 2s socket/managed-transformer wording in this section: socket 1s, adapter-owned bounded response body and explicit abort; API/attempt 3s/2s and body checks 3s retained. Raster policies and the separate worker lifecycle are unchanged. [Fresh evidence](../evidence/preview-transport-correction.md). / Emenda de transporte substitui socket 2s/transformer gerenciado desta seção: socket 1s, leitura limitada própria e abort explícito, mantendo demais prazos. Políticas raster/worker inalteradas.

This section supersedes the earlier worker-only/pending activation statements below, retained as implementation history. Provide `S3ImagePreviewPort` separately from attachments/mutations. The singleton worker owner is constructor-injected into the application-scoped AWS preview adapter. Image reads reuse ADR-0018's bounded transport: 1s connection, 2s socket, 3s API and 2s attempt budgets, plus 3s monotonic body checks, at most 1 MiB + 1 bytes and abort on every exit. Decode happens only after the managed transformer returns, with the separate five-second worker wait. These budgets do not establish a hard end-to-end real-time or native-memory bound. Refused/busy/failed worker output is never served partially.

Esta seção substitui os rótulos históricos de ativação pendente abaixo. Port de imagem separado de anexos/mutações; worker singleton injetado por construtor no adaptador AWS. Transporte limitado conforme ADR-0018, leitura até 1 MiB + 1 e abort em todas as saídas; decode fora do transformer com espera própria de cinco segundos. Orçamentos não garantem tempo real completo nem memória nativa limitada. Sem servir saída parcial.

Require `.png` with `image/png`, or `.jpg`/`.jpeg` with `image/jpeg`, case-insensitive, no MIME parameters and no nonidentity Content-Encoding. Verify PNG signature/chunk lengths/CRC/final IEND and reject APNG chunks; verify JPEG SOI/segment/scan framing and final EOI with no suffix or concatenated image. Refuse decoder warnings and failed decode. These guards plus re-encoding are not a complete format-conformance validator or malware detector. No EXIF orientation/fidelity promise; the original remains authoritative. Static PNG/JPEG only; images over the existing dimension/pixel/output policies are refused, never downscaled or truncated. Other formats remain unsupported.

Exigir extensão/MIME coerentes sem parâmetros e encoding identity/ausente. Conferir assinatura/chunks/CRC/IEND do PNG e recusar chunks APNG; conferir framing SOI/segmentos/scan/EOI JPEG sem sufixos ou concatenação. Recusar warnings/falha de decode. Não é validador completo nem antivírus, nem promessa de orientação EXIF/fidelidade. PNG/JPEG estáticos dentro dos limites, sem reduzir/truncar; demais formatos recusados.

Native shell GET `/s3/preview/image?bucket=…&key=…` validates the opaque target but performs no S3 read. Its single same-origin `<img>` GET `/s3/preview/image/content?bucket=…&key=…` reads and re-encodes the current object. The shell's 200 does not confirm image availability or object existence; only the image response can do so. No token cache, HEAD preflight, second content read, or version-consistent snapshot is claimed. Download may retrieve a newer original if the object changes between requests. Full detail offers an image link only as a filename/MIME hint; endpoint validation is authoritative. No automatic body fetch on listing/detail/drawer.

Shell GET nativo valida alvo opaco sem ler S3; um único GET da imagem lê/reencoda objeto atual. Status 200 do shell não confirma existência/disponibilidade; confirmação depende da resposta da imagem. Sem cache de token, HEAD prévio, segunda leitura de conteúdo ou snapshot consistente por versão. Download pode obter original mais recente se houver mudança. Link nos detalhes é indício, endpoint valida de fato; sem ler corpo na lista/detalhe/drawer.

Image success is fixed `image/png`, fixed inline name `preview.png`, no-store and unchanged security headers/CSP. Policy refusals are localized plain text with 415 unsupported metadata, 413 excessive input, 422 invalid image/decoder policy. Remote errors retain 400/403/404/501/502/503; worker busy/startup/timeout/interruption maps to 503. Native shell retains explanatory fallback, original attachment/back links and image alt text without JavaScript; local JS only updates translated loading/success/failure text and hides the broken image after failure, without HTML injection or new retries. A failed image element cannot expose the HTTP error body visually without JS fetch; the persistent generic fallback explains that limitation, while direct content requests retain localized reasons/status. Browser tests must cover both native and enhanced paths.

Sucesso: PNG/título inline fixos, no-store e headers/CSP preservados. Recusas textuais traduzidas: 415 metadados, 413 entrada excessiva, 422 imagem/política do decoder. Falhas remotas mantêm status; worker ocupado/falha/timeout/interrupção usa 503. Shell mantém fallback/download/voltar/alt sem JS; JS local só atualiza texto traduzido e oculta imagem quebrada, sem HTML ou retry. Elemento img não mostra corpo HTTP de erro; fallback genérico persistente explica e acesso direto mantém motivo/status. Testar caminhos nativo e melhorado. Validação consolidada com imagem nova permanece para o final; nome/jurídico pendentes.

Format references consulted on 2026-10-16: [W3C PNG third edition](https://www.w3.org/TR/png-3/) and [ITU-T T.81 JPEG](https://www.w3.org/Graphics/JPEG/itu-t81.pdf). These inform structural guards, not a claim of exhaustive conformance tests. / Referências oficiais orientam guardas, sem comprovar conformidade exaustiva.

## Worker implementation slice / Fatia implementada do worker

`RasterPreviewProcess` owns a single nonblocking semaphore per instance, generated temporary input/class/output files, a fixed Java executable from `java.home` and a five-second process wait budget. It extracts only the trusted JDK-only `RasterPreviewWorker.class` resource (at most 64 KiB), avoiding dependency on the parent process classpath. The worker gets 128 MiB maximum Java heap, one reported processor and headless mode. Its environment is cleared; Windows may add required `SystemRoot` itself, as allowed by the [ProcessBuilder contract](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/lang/ProcessBuilder.html). No inherited credential/Java-option variables are intentionally retained. On timeout/interruption the owner forcibly destroys and waits for the worker before cleaning its generated directory and releasing the slot. This wait is not a hard real-time guarantee if the operating system fails to terminate a process. Future application wiring must share one owner rather than create one per request.

`RasterPreviewProcess` possui semáforo não bloqueante por instância, arquivos temporários gerados e Java fixo de `java.home`, com espera de cinco segundos. Extrai só a classe confiável do worker (até 64 KiB), sem depender do classpath pai. Worker com heap máximo 128 MiB, um processador informado e headless. Ambiente limpo; Windows pode adicionar `SystemRoot` obrigatório conforme contrato oficial. Sem herdar intencionalmente credenciais/opções Java. Timeout/interrupção força encerramento e aguarda antes de limpar/liberar; não é garantia de tempo real se o SO falhar ao encerrar. Integração futura deve compartilhar um owner, não criar um por request.

The worker accepts only PNG/JPEG reader formats, at most 1 MiB input, 4096 per axis and 4,000,000 pixels, copies fresh ARGB pixels and encodes PNG through a 1 MiB output sink. ImageIO's internal output cache is memory-only inside the heap-limited child; the sink bound is not a claim that the encoder allocates at most 1 MiB. Stderr is discarded; partial output is never returned on nonzero exit. `ActiveProcessorCount=1` is not a CPU quota; heap is not a native-memory/RSS limit. This process is not a security sandbox, and there is no active S3 image endpoint. Filename/MIME/encoding checks and strict malformed/animation semantics remain activation gates. [Fresh worker evidence](../evidence/ux-5b-worker-results.md) is separate from the earlier codec spike.

Worker aceita formatos PNG/JPEG, entrada até 1 MiB, eixos até 4096 e 4.000.000 pixels; copia pixels ARGB e reencoda PNG com saída limitada a 1 MiB. Cache interno ImageIO fica na memória do filho com heap limitado; não significa alocação total de apenas 1 MiB. Stderr descartado e saída parcial nunca retornada em falha. Processador informado não é quota CPU; heap não limita memória nativa/RSS. Não é sandbox nem endpoint ativo. Validação de nome/MIME/encoding e semântica estrita/animação seguem pendentes; evidência nova separada do spike anterior.

## Direction / Direção

Keep ADR-0018 text preview unchanged. A future image preview must consume bounded object bytes through a dedicated read contract, require matching extension, MIME and actual format, decode a permitted raster and encode fresh pixels as PNG without carrying source metadata. Never serve the original bytes inline. Original attachment download remains unchanged under ADR-0008; CSP must not gain data URLs, external resources or inline scripts. No automatic body fetch from listings or the metadata drawer.

Manter texto da ADR-0018. Preview futuro exige leitura limitada própria, extensão/MIME/formato coerentes e reencode de pixels como PNG sem metadados da origem; nunca servir bytes originais inline. Download original/anexo e CSP permanecem; sem URLs data, recursos externos, scripts inline ou leitura automática na lista/drawer.

Candidate allowlist: PNG and JPEG only; reject SVG, GIF, WebP, HTML, PDF, archives, generic/conflicting MIME and nonidentity Content-Encoding. Candidate product limits: 1 MiB complete compressed input, dimensions at most 4096 per axis, at most 4,000,000 pixels and 1 MiB encoded output. Refuse rather than truncate. These are proposed conservative limits, not measured capacity or an implemented upload restriction. Animation handling and strict malformed/trailing-data rejection need an explicit production decision; the spike's trailing-data experiment proves only that its fixture's suffix is not copied.

Candidatas: apenas PNG/JPEG, sem SVG/GIF/WebP/HTML/PDF/compactados, MIME genérico/conflitante ou Content-Encoding não identity. Limites propostos: entrada completa de 1 MiB, 4096 por eixo, 4.000.000 pixels e saída de 1 MiB, recusando sem truncar. Não representam capacidade medida nem restrição de upload implementada. Animação e rejeição estrita de dados malformados/adicionais exigem decisão; o spike só comprova remoção do sufixo da fixture.

## Resource-isolation gate / Gate de isolamento de recursos

Image dimensions and input bounds alone do not bound decoder CPU, native allocations or output buffering. Do not promote the in-process experiment to a request handler. Investigate a short-lived worker JVM with explicit heap and wall-time limits, bounded concurrency and output sink, reliable forced termination/cleanup and no inherited credentials or Java option injection. A worker process is not an OS security sandbox. Proposed starting budgets (unverified): one concurrent worker, 128 MiB heap, five-second worker deadline, immediate refusal when busy. Establish end-to-end read/decode budgets separately; cancelling a future is not evidence that a decoder stopped.

Dimensões e bytes não limitam sozinhos CPU/alocações nativas/saída. Não promover experimento em processo para handler. Investigar JVM separada com heap/prazo, concorrência e saída limitados, encerramento/limpeza comprovados, sem credenciais herdadas nem injeção de opções Java. Processo não é sandbox do SO. Orçamentos iniciais propostos, não verificados: um worker, heap 128 MiB, cinco segundos, recusa imediata se ocupado. Orçamento completo de leitura/decode separado; cancelar future não comprova interrupção do decoder.

## Activation gates and validation order / Gates de ativação e ordem de validação

1. Local codec experiment and honest evidence, without runtime route changes.
2. Bounded worker implementation: success, corrupt/truncated inputs, dimension/pixel boundaries, noisy output, timeout, concurrency, interruption, failed startup and cleanup tests. Verify packaged fast-jar classpath and resource ownership; do not assume the test classpath represents the runtime.
3. Dedicated application/AWS/web contracts, same-origin fixed `image/png` response, no-store on all outcomes, unchanged security headers, encoded opaque keys, localized refusal/loading/error states, explicit original download and native no-JS fallback. Define any page-to-image consistency semantics before implementation; do not add an unbounded token cache.
4. Local JVM and focused browser checks in both languages/themes; no silent baseline regeneration.
5. At the end, build a new image and run consolidated Docker/runtime codec/native-library and browser validation as requested by the user. That final verification is deferred, not waived. Human accessibility and legal/name validation remain pending.

Ordem: spike local; worker limitado com casos de falha/limites/limpeza e fast-jar; contratos de camadas/HTTP/UX seguros e bilíngues; verificações locais; somente ao final imagem nova e validação consolidada Docker/runtime/navegador. Não regenerar baselines silenciosamente. Aceite humano e validação jurídica/do nome continuam pendentes.
