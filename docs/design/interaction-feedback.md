# Interaction feedback standard / Padrão de feedback das interações

Authority / Autoridade: [ADR-0033](../decisions/ADR-0033-interaction-feedback.md). Applies to current and future services in Quarkus/Qute/HTMX with local JavaScript. / Aplica-se aos serviços atuais e futuros na stack existente.

## English

Table action focus is individual: row `:focus-within` may indicate the row, but must never apply another control's selected/border/underline treatment. In particular, focusing Details/Delete must not highlight Download. Keep each action's own `:focus-visible` indication.

Reveal-order correction: a checked fragment's presence alone is insufficient. Initial action dialogs must finish component initialization and htmx settle before revealing on the next render frame, with loading text cleared and `aria-busy=false` before `showModal`. Inspectors initialize their controls before reveal as well. Guard queued reveals against Escape, replacement and page exit. Tests must inspect state at the synchronous reveal call, not just a later DOM snapshot. Download uses the same transparent icon action as adjacent controls, retaining accessible name and real keyboard focus styling.

Use `beginInteractionFeedback` in `app.js` for asynchronous read/navigation/clipboard presentation. It marks the trigger busy immediately, reveals its indicator/announcement after the shared 200 ms threshold and returns an idempotent `finish()`. Always finish on success, refusal, failure, cancellation, replacement and page exit as appropriate. Ownership prevents an old completion from clearing a newer interaction. Do not duplicate timers or create a framework/application module for this behavior. The helper does not validate HTTP, authorize work or cancel mutations.

| Interaction                                  | Required behavior                                                                                                                                                                                                                            |
| -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Local filter, disclosure, Preferences toggle | Immediate local response; no artificial loading state.                                                                                                                                                                                       |
| Native read navigation                       | Keep normal links, history and preferences; source feedback only, cleaned on pagehide/pageshow. Never intercept attachments or signed URLs to claim download completion.                                                                     |
| Open action/review or inspector              | Fetch only after explicit interaction; verify current request, route/origin, status, MIME, marker and selected escaped Qute fragment. Open the named dialog with content already present, not an empty loading window.                       |
| Read another inspector view                  | Keep the current view/title until the checked replacement arrives; retain geometry and valid focus. On failed selection, show explicit failure/retry without presenting previous object metadata as the new target.                          |
| Refresh listing                              | Keep the list while reading. Preserve preferences, filter, cursor, scroll and focus where valid. Reject stale/unmarked/wrong responses; retain old list with failure text. No full-shell replacement.                                        |
| Clipboard                                    | Suppress duplicate calls, report actual API success/failure and preserve selectable fallback. No modal or simulated success.                                                                                                                 |
| Form submission/upload                       | Disable duplicate submission and expose real submitting state immediately, without waiting for the read-feedback threshold. Show actual transfer progress only; preserve field errors and original files.                                    |
| Durable operation                            | Report accepted/preparing/running/terminal state from the local journal. Preparation with an exact target is real work, not a generic loading placeholder. Do not wait silently for a long operation to finish or show invented percentages. |
| Preview                                      | Preserve the current isolated formats/limits. Encoding/decoding can show real availability progress; a valid shell is not proof that image/content validation succeeded.                                                                     |
| Notification                                 | Compact viewport toast with named close icon. Confirmed success expires after five visible seconds, paused by hover/focus/hidden document. Pending and attention outcomes remain until dismissed. No focus stealing or promise of undo.      |

Escape can abandon a pending read or close a permitted dialog; it never promises cancellation/rollback of a sent mutation. Repeated pending openings must not create duplicate requests or confirmations. A new selection supersedes its obsolete read. Existing no-retry/CSRF/CSP/exact-target/backend rechecks remain authoritative. Do not cache/reuse forms, selected files, credentials, signed URLs or CSRF tokens, prefetch mutations, poll emulator health or add a global health cache. Home remains independent of the emulator.

Required review for a new component: classify its interaction, reuse the applicable controller/helper, keep useful canonical fallback and bilingual labels, test quick and held reads, repeated clicks, Escape, error/stale/invalid responses, keyboard/focus and reduced motion. Exercise relevant states in both languages/themes at 390, 1366 and 1440 px. A held response must not reveal an empty dialog; a failed response must not be disguised as success. Report only checks run. Daily JVM/local tooling and MiniStack-only Docker still apply.

## Português

Foco das ações da tabela é individual: `:focus-within` da linha pode indicar a linha, mas nunca aplicar seleção/borda/sublinhado a outro controle. Focar Detalhes/Excluir não destaca Download. Preservar `:focus-visible` do próprio acionador.

Correção da ordem de abertura: presença do fragmento verificado não basta. Diálogos iniciais concluem inicialização e settle do htmx antes de revelar no próximo frame, sem texto de carregamento e com `aria-busy=false` antes de `showModal`. Inspector também inicializa controles antes de abrir. Proteger revelação agendada contra Escape, substituição e saída. Testar estado síncrono na chamada de abertura, não só snapshot posterior. Download usa ícone transparente como ações vizinhas, preservando nome acessível e foco real por teclado.

Reutilizar `beginInteractionFeedback` em `app.js` para apresentação de leitura/navegação/clipboard assíncronos. Marca o botão ocupado imediatamente, mostra indicador/anúncio após o limiar comum de 200 ms e retorna `finish()` idempotente. Finalizar em sucesso, recusa, falha, cancelamento, substituição e saída da página, conforme o fluxo. Controle de propriedade impede conclusão antiga de apagar feedback novo. Não duplicar timers nem criar framework/módulo de aplicação para isso. O helper não valida HTTP, autoriza trabalho ou cancela mutações.

| Interação                              | Comportamento obrigatório                                                                                                                                                                                                                                |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Filtro local, disclosure, Preferências | Resposta local imediata; sem carregamento artificial.                                                                                                                                                                                                    |
| Navegação nativa de leitura            | Preservar links, histórico e preferências; feedback no botão, limpo em pagehide/pageshow. Não interceptar anexos/URLs assinadas para alegar conclusão de download.                                                                                       |
| Abrir ação/revisão ou inspector        | Buscar após interação explícita; verificar requisição atual, URL/origem, status, MIME, marcador e fragmento Qute escapado. Abrir diálogo nomeado já com conteúdo; sem janela vazia de carregamento.                                                      |
| Trocar leitura no inspector            | Preservar conteúdo/título atuais até substituição verificada, mantendo geometria/foco. Falha explícita com nova tentativa, sem apresentar metadados anteriores como alvo novo.                                                                           |
| Atualizar listagem                     | Manter dados durante leitura, preferências, filtro, cursor, rolagem e foco válidos. Recusar respostas obsoletas/sem marcador/incorretas; manter lista anterior com aviso de falha. Sem substituir shell.                                                 |
| Clipboard                              | Bloquear duplicidade, comunicar resultado real da API e manter cópia manual selecionável. Sem modal ou sucesso simulado.                                                                                                                                 |
| Submeter formulário/upload             | Bloquear duplicidade e indicar envio real imediatamente, sem esperar o limiar de leitura. Progresso de transferência real, erros junto ao campo e arquivo original preservado.                                                                           |
| Operação persistente                   | Estado aceito/em preparação/em execução/final confirmado pelo registro local. Preparação com alvo exato é trabalho real; não esperar silenciosamente conclusão longa nem inventar percentual.                                                            |
| Prévia                                 | Preservar isolamento, formatos e limites. Codificação/decodificação pode indicar disponibilidade real; shell válido não comprova validação do conteúdo.                                                                                                  |
| Aviso                                  | Toast compacto na viewport com ícone de fechar nomeado. Sucesso expira após cinco segundos visíveis, com pausa por mouse/foco/documento oculto. Pendência e resultados que exigem atenção permanecem até dispensa. Sem roubar foco ou prometer desfazer. |

Escape abandona leitura pendente ou fecha diálogo permitido; não promete cancelar/desfazer mutação enviada. Repetição de abertura não cria requisições/confirmações duplicadas. Nova seleção substitui leitura obsoleta. Preservar no-retry, CSRF/CSP, alvo exato e novas verificações backend. Sem cache/reuso de formulário, arquivo, credencial, URL assinada ou CSRF; sem prefetch de mutações, polling de saúde ou cache global. Home independente do emulador.

Revisão obrigatória de componente novo: classificar interação, reutilizar controlador/helper adequado, manter fallback canônico útil/rótulos bilíngues e testar resposta rápida/retida, repetição, Escape, falha/resposta inválida/obsoleta, teclado/foco e movimento reduzido. Exercitar estados relevantes em idiomas/temas e larguras indicadas, sem presumir cobertura de todas as combinações. Resposta retida não mostra janela vazia; falha não vira sucesso. Relatar somente checks executados. Continuar JVM/ferramentas locais e Docker somente MiniStack.
