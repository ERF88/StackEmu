# Interface responsiveness review / Revisão da fluidez da interface

Date / Data: 2026-10-27. Host JVM, Chrome and local MiniStack only; no new application image. / Somente JVM, Chrome e MiniStack locais; sem nova imagem da aplicação.

## Findings and changes / Diagnóstico e ajustes

Three local preparation samples took 1459–1993 ms (median 1927 ms), while warmed upload forms opened in 53–73 ms. The fixed two-second local-record polling interval delayed an already prepared review. State checks now start promptly and back off to two seconds without overlapping cycles or hidden-document polling. They query the local journal, never emulator health.

Três amostras locais de preparação levaram 1459–1993 ms (mediana 1927 ms), enquanto formulários de upload aquecidos abriram em 53–73 ms. A espera fixa de dois segundos atrasava a revisão já preparada. Consultas locais agora começam rapidamente e espaçam até dois segundos, sem ciclos sobrepostos ou polling em documento oculto. Consultam o registro local, nunca saúde do emulador.

Compatible bucket/object listings now refresh through marked, escaped read fragments with exact URL, status, content type, target and request checks. Filters, cursor, table scroll and valid focus are retained. A rejected response leaves the prior listing with explicit failure feedback. One follow-up handles completion racing an in-flight read. Creating a folder in an enhanced dialog stays in the current folder; canonical return links remain useful without JavaScript.

Listagens compatíveis atualizam por fragmentos de leitura marcados/escapados, com validação de URL, status, tipo, alvo e requisição. Preservam filtro, cursor, rolagem da tabela e foco válido. Resposta recusada mantém a listagem anterior e aviso explícito; uma atualização posterior trata conclusão durante leitura. Criar pasta em diálogo aprimorado mantém a pasta atual; retornos canônicos permanecem úteis sem JavaScript.

Confirmed notifications update in place and stay dismissible within the viewport, without automatic disappearance, layout displacement or a full-page reload. Pending/completed/partial/uncertain wording follows real local state; no fabricated progress, undo or mutation retry. Native navigation remains for a different destination and canonical operation pages.

Avisos confirmados atualizam localmente e ficam dispensáveis na viewport, sem desaparecimento automático, deslocamento do layout ou recarga completa. Texto de andamento/conclusão/falha parcial/incerteza acompanha estado local real; sem progresso fictício, desfazer ou retry de mutação. Navegação nativa mantida para destinos diferentes e páginas canônicas de operação.

## Evidence / Evidência

### Reported regression follow-up / Correção da regressão relatada

Screenshot follow-up: the reported border belonged to the Download action in the object table. The legacy `.resource-table tbody tr:focus-within .table-action` selector gave Download a focus border/underline when any row control was focused. The previous panel-only correction did not cover this selector. Removed the obsolete class/rules; row indication remains, while each control retains only its own focus-visible treatment. Seven browser cases passed, including name/Details/Delete focus versus Download in light/dark and actual keyboard focus on Download (`work/table-action-focus-browser.log`). Captures were inspected. Java 25/Maven package verification and frontend checks passed; Java tests were intentionally skipped for this CSS/template-only correction (`work/table-action-focus-build.log`, `work/table-action-focus-checks.log`).

Complemento da captura: borda relatada era do Download na tabela. Seletor legado aplicava borda/sublinhado ao Download quando qualquer controle da linha recebia foco. Correção anterior do painel não abrangia essa regra. Classe/regras obsoletas removidas; indicação da linha mantida e foco individual preservado. Sete casos passaram, incluindo foco em nome/Detalhes/Excluir sem destacar Download e foco real por teclado nele, nos temas claro/escuro. Capturas inspecionadas, empacotamento Java 25/Maven e checks frontend aprovados; testes Java ignorados intencionalmente nesta correção só de CSS/template. Logs indicados acima.

The maintainer reported a recurring empty upload opening and Download highlight. A fresh-session post-event probe did not reproduce an empty dialog or automatic Download focus (`work/reported-ui-regression-probe.log`). A synchronous `showModal` probe then exposed an earlier reveal: the upload content was still `aria-busy=true` and its enhancement hint was not initialized (`work/reveal-order-before.log`). Later mutation-observer snapshots had missed that order. Action dialogs now reveal after checked swap, component initialization and htmx settle, on the next render frame with busy/loading state already cleared. Inspectors initialize their controls before reveal. Escape/replacement/page-exit guards cancel queued openings; no minimum loading duration or form cache was added.

O mantenedor relatou retorno da abertura vazia e destaque no Download. Probe posterior aos eventos, em sessão nova, não reproduziu janela vazia ou foco automático. Probe síncrono de `showModal` encontrou abertura anterior à conclusão: conteúdo ainda ocupado e hint do upload não inicializado. Snapshots posteriores perdiam essa ordem. Ações agora revelam após swap verificado, inicialização e settle, no próximo frame e já sem estado ocupado/carregamento. Inspector inicializa controles antes de revelar. Escape/substituição/saída protegem a abertura agendada; sem espera mínima ou cache de formulários.

Download had a permanently filled neutral button even without `primary` or focus. It now shares the transparent icon treatment of adjacent actions, with the same accessible name/tooltip and normal keyboard-focus affordance. HTML cache policy was also incomplete: Home/S3/canonical object pages now use `no-store`, while fingerprinted JS/CSS remain immutable and match their actual bytes. This cache gap was observed separately; it is not claimed as the proven cause in the maintainer's previously open tab. Packaged restarts still require full-page navigation/reload, not only listing refresh.

Download tinha fundo neutro preenchido mesmo sem `primary` ou foco. Agora compartilha ícone transparente das ações vizinhas, com nome/tooltip e foco real preservados. Política de cache HTML incompleta também foi corrigida: páginas HTML usam `no-store`, assets versionados mantêm cache imutável com hash correspondente aos bytes. Lacuna de cache observada separadamente, sem alegar causa comprovada na aba anterior do mantenedor. Reinício empacotado requer navegação/recarga completa, não apenas atualização da lista.
